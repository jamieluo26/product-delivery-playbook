# Product Delivery Playbook

**把会议中的一句话，追踪到需求、检查项和交接记录。**

Evidence-first product delivery notes, blank tables and a fully synthetic worked example.

这是一套给产品经理、研发协作者和 AI 助手使用的文字工作法。它帮助审阅材料和形成草案；不是自动执行系统，也不会因为写出“通过”就替代真实测试或人的确认。

[一页案例走读](examples/reading-list-walkthrough.md)展示“个人阅读清单”从虚构讨论到追踪表的过程。所有人物使用中性角色标签；没有真实会议或产品数据。

## 使用方式

准备有明确来源位置的材料，选一个工作说明，按表形成草案，再由相关人员核对决定和实际证据。可把说明作为 AI 助手的任务参考；本仓库不安装 Skill，不提供模型、转写或外部服务。

工作法来自对三类通用文本审阅机制的重新组织：会议决策证据、需求与验收关系、产品资产交接。这里的说明、表格和案例新写，不包含原运行包、固定系统协议、公司规则或真实材料。

示例的产生方式与验证范围见[说明](VERIFICATION.md)。

## 判断结果前，先问三件事

1. 结论对应哪一段实际读过的材料？
2. 它是已确认的决定、提出的方案，还是仍缺证据的问题？
3. 目前证明的是文本关系、真实行为，还是人的验收？

缺材料就保留缺口。关系能连通不代表真实测试通过，最新一句话也不会自动消解旧冲突。
